Open source · Shell · Agent tooling

One mind.
Four hands.

opencode Swarm is a multi-agent kit for opencode: one orchestrator that plans and delegates, four specialists that code, review and test in parallel — all with opencode's native subagents. No extra frameworks, no extra dependencies, no extra cost.

Works with any provider/model. By default every agent inherits your current session model.

What's inside.

01 / PRIMARY

Orchestrator

Decomposes tasks, fans out to workers in parallel via the Task tool, synthesizes results, then verifies — with a maximum of two review rounds.

02 / WORKERS

Four specialists

Planner writes file-level subtasks with goal, scope, acceptance criteria and dependencies. Coder implements. Reviewer returns a file:line verdict. Tester runs builds and tests, never edits.

03 / SKILLS

Three skills

Swarm orchestration (when to fan out), task decomposition (how to split multi-file work), and review verdict (the independent review gate format). They trigger on keywords like swarm, decompose, review.

04 / COMMAND

/team

One command runs the whole plan → parallel code → review → test loop. Switch to the orchestrator mid-session with Tab, or invoke any worker directly with @swarm-planner, @swarm-coder and friends.

Usage & setup.

# install (default: inherit your current model)
git clone https://github.com/sarimmohib/opencode-swarm-integration.git
bash opencode-swarm-integration/install.sh

# optional: pin models per role
bash install.sh --model anthropic/claude-sonnet-4-6
bash install.sh --orchestrator-model ... --subagent-model ...

# then restart opencode (config loads once at startup)
opencode agent list | grep -E "orchestrator|swarm-"

# run the swarm
/team <task>   # plan → parallel code → review → test
--model MPin all agents to one model. With no flags, orchestrator and subagents inherit your session model and variant — recommended, and free-tier (Zen) users need nothing.
--orchestrator-modelPin only the orchestrator — e.g. a strong model for planning/delegation.
--subagent-modelPin only the four workers — e.g. a fast model for execution. Combine both for split roles.
--variant VReasoning effort (minimal → xhigh) for pinned agents only. Inherited agents always follow your session variant.
⚠ Known gotchaNever set bash: deny on an agent. Verified live on opencode 1.18.31 (Zen free tier): removing the bash tool makes the gateway reject requests with "free tier can only be used in OpenCode". edit: deny is fine and encouraged for reviewer/tester/planner. Restrict bash commands, not the tool itself.
